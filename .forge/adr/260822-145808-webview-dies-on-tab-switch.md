# 탭을 전환하면 웹뷰가 죽는다 — 메모리를 지키고 상태를 따로 보존한다

`retainContextWhenHidden: false` 를 유지한다. 즉 **배경 탭의 웹뷰는 파괴되고, 되돌아오면
처음부터 다시 만들어진다.** 대신 사라지면 곤란한 것(측정 · 카메라 · 표시 토글 · 측정 모드)은
웹뷰의 `setState`/`getState` 로 저장·복원한다.

이 결정을 내린 이유는 리소스다. 뷰어 하나가 WebGL 컨텍스트 · Babylon 엔진 · 350 KB IBL 텍스처 ·
렌더 루프를 들고 있으므로, 열린 탭마다 그것을 살려 두면 3D 뷰어를 여러 개 켠 것만으로 PC 가
무거워진다. `retainContextWhenHidden: true` 는 정확히 그 상태를 만든다.

## 측정한 사실

추측이 아니라 실제 VS Code 1.134.0 에서 확장 호스트 테스트로 재어 확인했다. 다시 찾아내는 데
비용이 크므로 여기 남긴다.

1. **보이는 웹뷰 하나만 살아 있다.** 탭 3개를 고정해 열고 각 세션에 `postMessage` 를 보내면
   보이는 것만 `true`, 배경 탭은 **모두 `false`** 였다(문서상 "not deliverable to a dead webview").
   → 따라서 **동시 뷰어 개수 상한은 값이 거의 없다.** 살아 있는 컨텍스트 수는 화면에 보이는
   뷰어 수와 같고, 그건 사용자가 만든 편집기 그룹 수로 이미 제한된다. 상한 기능을 만들지 않는다.
2. **`resolveCustomEditor` 는 문서당 딱 한 번만 호출된다.** 탭을 여러 번 왕복해도 호출 수는 1 이었다.
   → **호스트가 복귀 시점에 상태를 밀어 넣는 방식은 불가능하다.**
3. **웹뷰 스크립트는 복귀할 때마다 다시 실행된다.**
4. **`setState`/`getState` 는 그 파괴/재생성 사이클을 넘어 살아남는다.** 왕복하며 카운터가
   1 → 2 로 증가했다. → 상태 보존의 유일하고 올바른 채널이다.

## 부수적으로 드러난 것

파트 4/4 는 "측정은 세션 한정 — **탭을 닫으면** 사라진다"고 기록했다. 실제로는 위 (1)(3) 때문에
**탭을 전환하기만 해도** 사라졌다. 문서화되지 않은 결함이었고, 이 ADR 의 상태 보존이 그것을 고친다.

## Consequences

- **탭 전환마다 모델과 IBL 을 다시 로드하는 지연이 남는다.** 이건 메모리를 위해 받아들인 대가다.
  없애려면 `retainContextWhenHidden: true` 로 가야 하고, 그건 이 결정의 목적과 정반대다.
- **보존 범위는 세션 한정이다.** VS Code 를 재시작하면 사라진다. 재시작 후까지 남기려면 측정이
  영구 데이터가 되고, "모델 파일이 수정되면 저장된 좌표가 조용히 거짓이 된다"는 무효화 문제를
  풀어야 한다 — 측정 도구에서 특히 위험하므로 범위 밖으로 둔다.
- **단위 선택은 여기에 넣지 않는다.** 이미 호스트의 `workspaceState` 에 파일별로 저장된다
  (ADR `260822-115455c`). 두 곳에 두면 어긋난다.
- **Inspector 상태는 복원하지 않는다.** 복원하면 탭 전환마다 chunk 24개(수 MB)를 다시 파싱해
  이 ADR 의 목적과 정면으로 충돌한다. 원하는 사용자는 `modelLens.inspectorOnStart` 를 쓴다.
