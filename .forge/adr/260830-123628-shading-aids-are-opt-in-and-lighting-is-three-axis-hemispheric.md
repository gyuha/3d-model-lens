# 표시 보조는 기본 꺼짐이고, 조명 보조는 3축 반구광으로 만든다

STL 모델의 형태가 읽히지 않는 문제를 **표시 보조**(CONTEXT.md) 세 개로 푼다 — 조명 · 크리스 모서리 ·
법선 컬러링. 셋 다 **전역 VS Code 설정으로 저장되는 기본 꺼짐 토글**이고, 조명 보조는 흔한
3점 조명이 아니라 **X·Y·Z 축마다 반구광 하나씩** 두는 구조다.

두 선택 모두 실측 뒤에 뒤집힌 결과다. 그 경위가 이 문서의 값이다.

## 왜 방향광 키 라이트로는 안 되는가 (실측)

처음 계획은 교과서적인 리그였다 — 카메라 쪽 방향광 키 + 반구광 필 + 환경광 감소. 두 번 만들어
같은 상자를 같은 각도에서 찍었다.

| 시도 | 정면 | 오른쪽 면 | 윗면 |
|---|---|---|---|
| 베이스라인 | 연한 라벤더 | 연한 라벤더 | 흰색 |
| 방향광 키 (`intensity 1.5`) | 더 하얗게 포화 | 더 하얗게 포화 | 흰색 |
| 방향광 키 + 노출 `0.6` · 대비 `1.5` | 따뜻한 회색 | **따뜻한 회색 (동일)** | 밝은 청백 |

**첫 시도의 실패 원인은 광원이 약해서가 아니라 포화였다.** 기본 재질의 `baseColor` 가 `0.78` 로
이미 밝아, 빛을 더하면 전부 흰색으로 클리핑돼 대비가 오히려 사라진다. 노출을 낮춰 여유를 만들자
**위아래는 갈렸지만 정면과 측면은 끝내 같은 톤이었다** — 반구광의 하늘/바닥 대비는 `N·up` 하나만
보므로 수평면끼리는 구별하지 못하고, 방향광 하나는 그 축 하나만 밝힌다.

## 왜 3축 반구광인가

축마다 반구광을 두고 **하늘색과 바닥색을 서로 다르게** 준다. 반구광은 반대쪽 반구도 `groundColor`
로 비추므로 **어느 방향을 보든 검게 죽는 면이 없고**, 세 축을 겹치면 면의 방향이 곧 색이 된다.
같은 상자에서 정면=분홍 · 측면=민트 · 윗면=흰색으로 갈렸다.

이것이 사용자가 처음 제안한 *"조명을 각도별로 다른 색으로 비친다"* 를 그대로 구현한 것이며,
**사실적이지 않은 대신 방향이 읽힌다** — 표시 보조의 판단 기준이 그것이다(CONTEXT.md).

**기각한 대안: 축마다 방향광 3개.** 방향광은 한쪽만 비추므로 `-X`·`-Y`·`-Z` 를 향한 면이 검게
죽는다. 반대편에 3개를 더 두면 6개가 되고, 재질의 `maxSimultaneousLights` 기본값 4를 넘긴다.

## 왜 기본 꺼짐인가 (알고도 받아들인 대가)

**세 토글 모두 기본이 꺼짐이므로, 아무것도 건드리지 않은 첫 화면은 지금과 똑같이 평평하다.**
즉 이 작업은 **문제를 보고한 사람이 체크박스를 찾아내야만** 해결된다. 이 대가를 명시적으로
검토하고 사용자가 선택했다 — 기존 외형이 완전히 보존되는 쪽을 택한 것이다.

되살릴 신호: 형태가 안 보인다는 보고가 반복되는데 토글 사용률이 낮다면, 조명 보조의 기본값을
켜짐으로 바꾸는 것이 다음 후보다. 그때 이 문서의 실측 표가 근거다.

## 왜 전역 설정인가

Display 섹션의 기존 컨트롤이 **전부 전역 VS Code 설정**이다 — `modelLens.grid`,
`modelLens.background`. 반면 웹뷰 로컬 저장(`Vertex snap`)은 Measure 섹션에, 저장하지 않는 것
(`Inspector`)은 Debug 섹션에 있다. **이 저장소에서는 섹션이 곧 지속성 계층**이므로, Display 에
들어가는 것은 전역 설정이어야 한다. "난 모델을 이렇게 본다"는 파일이 아니라 사람에게 속한다.

부수 효과로 **`VIEWER_STATE_VERSION` 을 건드리지 않는다.** ADR `260822-233935` 가 경고한
"패널 토글을 되살리려면 지속성도 새로 붙여야 한다"는 함정을 전역 설정이 통째로 피해 간다 —
웹뷰 저장 상태에 필드를 더하지 않으므로 사용자의 측정값을 버릴 위험이 없다.

## STL 은 웰딩이 필요 없다 — 처음 판단은 틀렸다

계획 초기에 *"STL 은 정점을 공유하지 않으니 `enableEdgesRendering` 이 와이어프레임이 될 것"*
이라고 봤다. **틀렸다.** 실제 로더 출력으로 재보니:

```
cube.stl  정점 36 · 삼각형 12 · 고유 좌표 8   ← 실제로 공유하지 않음
enableEdgesRendering → 라인 정점 48 = 모서리 12개  ← 정육면체의 실제 모서리 수
  checkVerticesInsteadOfIndices  false / true  동일
  epsilon                        0.95 / 0.999  동일
```

**웰딩하지 않고도 크리스만 정확히 나온다.** 그러므로 `forceSharedVertices()` 를 **쓰지 않는다** —
쓰면 법선이 평균돼(실측: 정육면체 법선이 `(±0.58,±0.58,±0.58)` 로 뭉개짐) 각진 면이 매끈해지고,
STL 이 표현하려던 평면성이 사라진다. 미래에 "모서리가 이상하다"는 보고가 와도 **웰딩은 답이 아니다.**

남은 미지수는 정확성이 아니라 **큰 메시에서의 생성 비용**이다. 이 저장소의 픽스처는 전부 삼각형
수십 개라 그 비용을 잰 적이 없다 — 계획이 대형 픽스처를 만들어 실측한 뒤 상한 정책을 정한다.
**지금 임의의 상한 숫자를 지어내지 않는다.**

## Consequences

- 설정 세 개가 공개 API 가 된다. 한번 내보내면 이름을 바꾸거나 없앨 때 사용자의 `settings.json`
  이 깨지므로, 이름은 릴리스 전에 확정해야 한다.
- **법선 컬러링은 조명을 무력화한다** — 조명 없이 색을 직접 칠하므로, 켜져 있는 동안 조명 토글은
  화면에 아무 영향이 없다. UI 에서 조명 체크박스를 비활성화해 그 사실을 드러낸다(상태는 유지).
- **~~전 포맷에 적용된다.~~ 2026-08-30 뒤집혔다 — 아래 "실행 중 뒤집힌 것" 참조.** 모서리와 법선
  컬러링은 전 포맷이지만, **조명 보조는 STL 전용**이다.
- `scene.imageProcessingConfiguration` 의 노출·대비를 조명 보조가 바꾼다. 이는 씬 전역이므로
  **토글을 끌 때 원래 값으로 정확히 되돌려야 한다** — 되돌리지 않으면 꺼도 화면이 달라진 채 남는다.


## 실행 중 뒤집힌 것 — 전 포맷 적용은 절반만 유지된다

내보내기 전 검증에서 glTF 를 실제로 렌더해 보고 두 가지가 드러났다. **둘 다 "glTF 라서"가 아니라
각각 다른 원인이며, 하나는 설계 절충이고 하나는 그냥 결함이었다.**

**1. 조명 보조는 금속 재질에서 전제가 무너진다 → STL 전용으로 좁혔다.**
이 보조는 *"확산 표면이 사방에서 고르게 비치면 평평해 보인다"* 를 고치는 것인데, **금속은 확산
반사가 0** 이라 반구광을 아무리 얹어도 화면이 변하지 않는다. 그 상태에서 환경광만 낮추니
**더 어둡고 여전히 평평한** 결과가 됐다. 실측: glTF 기본 재질은 `metallic: 1` 이다(사양의 기본값).
STL 은 로더가 재질을 만들지 않아 우리 폴백(`metallic: 0`)을 받으므로 항상 안전하다. 그래서
**우리가 재질을 쥐고 있는 STL 에서만** 연다. 지원하지 않는 모델에서는 체크박스를 잠그고 이유를
툴팁에 적는다 — 눌러도 아무 일이 없는 것보다 낫다.

**정밀한 경계는 "확장자"가 아니라 "확산 재질인가"다.** 법선을 가진 비금속 glTF 라면 이 보조가
도움이 되지만, 지금은 확장자로 끊는다. 되살릴 신호: 비금속 glTF 에서 형태가 안 보인다는 보고.

**2. 법선 컬러링이 glTF 를 통째로 검게 칠했다 — 결함이었고 고쳤다.**
처음 셰이더는 `attribute vec3 normal` 을 읽었다. 그런데 **glTF 는 법선 생략을 허용하고**(사양상
렌더러가 평면 법선을 계산해야 한다) 이 저장소의 glTF 픽스처는 실제로 `속성=[position]` 뿐이다.
바인딩할 것이 없으니 `(0,0,0)` 이 들어와 `normalize` 가 NaN 이 되고 모델이 검게 나왔다. Babylon 의
PBR 은 화면 도함수로 때우기 때문에 평소 렌더에서는 드러나지 않던 문제다.

**법선 속성을 읽지 않고 화면 도함수로 면 법선을 구하도록 바꿨다.** 속성이 있든 없든 동작하고,
이 보조가 원하는 것은 정점 법선이 아니라 **면 방향**이라 오히려 더 맞다. 부호는 감김이 아니라
**시선**으로 정한다 — `gl_FrontFacing` 을 쓰면 행렬식이 음수인 모델(STL 손잡이 보정이 X 를 뒤집는다)
에서 색이 통째로 보색이 된다(실제로 glTF 가 STL 과 정반대 색으로 나왔다).

**3. 모서리는 영향이 없다.** Babylon 의 크리스 판정은 위치에서 면 법선을 직접 구하므로 법선 속성이
없는 glTF 에서도 정확히 나온다(실측: 상자 → 모서리 12개). 전 포맷 그대로 둔다.
