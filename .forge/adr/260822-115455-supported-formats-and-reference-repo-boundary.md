# 지원 포맷을 glTF / GLB / STL로 한정하고, 참고 레포 코드는 복제하지 않는다

이 확장의 출발점이 된 참고 레포 `tatsy/vscode-3d-preview`는 three.js로 obj / off / ply / pcd / stl / xyz 여섯 포맷을 다루는 연구용 뷰어다. 우리는 Babylon.js를 쓰기로 했고, Babylon의 기본 로더는 glTF 중심이다 — OFF / PCD / XYZ는 로더가 아예 없고, `.ply`는 로더가 있으나 Gaussian Splat용이라 삼각형 메시 PLY는 사실상 미지원이다. 커스텀 파서 세 개를 쓰는 대신 **glTF / GLB / STL 세 포맷으로 한정**하고, 남은 노력을 이 확장의 실제 목적인 측정 기능에 집중한다. OBJ도 초기 논의에서는 포함했으나 최종적으로 제외했다(MTL·텍스처 형제 파일 해결 부담 대비 가치가 낮음).

같은 결정의 다른 면: 참고 레포는 **GPL-3.0**이고 이 프로젝트는 MIT다. 참고 레포는 **아키텍처 참조로만** 사용하며 코드를 복사하지 않는다(Babylon.js는 Apache-2.0으로 MIT와 호환). 이 경계를 넘는 순간 라이선스가 감염되므로, 참고 레포에서 아이디어를 가져올 때도 구현은 새로 쓴다.

## Consequences

- 포인트 클라우드 지원은 이 확장의 범위 밖이다. 요구가 생기면 별도 파서 + 별도 측정 UX(면에 스냅할 것이 없음) 설계가 필요하다.
- Q2에서 논의한 "텍스트 포맷을 뷰어가 가로채는" 문제는 `.gltf` 하나로 축소됐다.
