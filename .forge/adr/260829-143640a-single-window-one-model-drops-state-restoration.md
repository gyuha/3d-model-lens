# 창 하나에 모델 하나 — 그리고 상태 복원 코드를 버린다

데스크톱 앱은 **한 창에 한 모델**을 띄운다. 탭 바를 만들지 않고, 동시에 여러 모델을 보려면 새 창을 연다.
이 결정에 따라 `viewerState.ts` 의 **직렬화/복원 경로를 제거한다.**

## 맥락

원본 ADR `260822-145808` 은 "배경 탭의 웹뷰는 파괴된다"는 VS Code 동작을 받아들이고, 대신 사라지면
곤란한 것(측정 · 카메라 · 표시 토글 · 측정 모드)을 웹뷰 state 에 직렬화해 되돌아올 때 복원한다는
결정이었다. 목적은 **WebGL 컨텍스트가 탭 수만큼 쌓이지 않게 하는 것**이었다.

Tauri 창은 배경으로 가도 파괴되지 않는다. 즉 **복원할 대상 자체가 없다.** 그 코드를 남겨두면
아무것도 트리거하지 않는 경로가 230줄짜리 파일 안에 남아, 다음 사람이 그것을 살아 있는 기능으로 읽는다.

탭 바를 직접 만드는 선택지도 있었다. 그러면 VS Code 경험이 가장 가깝게 재현되지만, 탭 UI · 탭별
상태 관리 · 씬 교체/파괴 정책이 전부 신규 코드가 된다. 원본에 없던 것을 만드는 일이고,
"기능을 그대로 유지"라는 요구는 뷰어와 측정에 관한 것이지 VS Code 의 탭에 관한 것이 아니다.

## 결정

- 창 하나에 모델 하나. 다른 파일을 열면 현재 모델을 **교체**한다.
- 동시에 여러 모델을 보려면 **새 창**을 연다. 창끼리 상태를 공유하지 않는다.
- `viewerState` 의 상태는 **메모리에만** 둔다. 직렬화하지 않는다.
- 따라서 [[뷰어 세션]] 의 경계가 다시 정의된다: 원본에서는 "탭이 닫힐 때"였고, 여기서는
  **"다른 파일을 열거나 창을 닫을 때"** 다. 측정이 폐기되는 지점도 정확히 그 경계다.

## 결과

- 원본 ADR `260822-145808` 은 이 앱에서 **무효**다. 그 문서는 아카이브로만 남는다.
- "측정은 세션 스코프이며 파일로 저장하지 않는다"는 원본 원칙(`260822-115455c`)은 **그대로 유지된다** —
  오히려 복원 경로가 사라져 더 곧이곧대로 지켜진다.
- 파일별 [[모델 단위]] 기억만은 예외로 디스크에 남는다. 그것은 세션 상태가 아니라
  "이 파일은 mm 로 읽는다"는 사용자의 판단이고, 원본에서도 세션과 다른 층에 저장됐다.
- 창을 여러 개 띄우면 WebGL 컨텍스트와 Babylon 번들이 창마다 따로 올라간다. 원본이 피하려던 비용이지만,
  여기서는 **사용자가 명시적으로 창을 열 때만** 발생한다는 점이 다르다.
